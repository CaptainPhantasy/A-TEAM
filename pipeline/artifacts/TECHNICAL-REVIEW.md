# Technical Review: FLOYD Anvil HTML Artifact

## Executive Summary
The spec is solid for a single-file HTML artifact. No Category A blockers. Two Category B items identified and resolved below. Technically feasible with vanilla HTML/CSS/JS. Primary risk is prompt generation quality — the template engine must be well-structured to produce consistent, high-quality output.

## Blocker Report

### Category A: Blockers (0 remaining)
None.

### Category B: High Risk Items (0 remaining after resolution)

- **B-1**: Spec says "objective must start with a verb" — runtime verb detection in JS is unreliable without NLP.
  - **Resolution**: Change validation to: "must be at least 10 characters and start with a capital letter." Add helper text showing verb-led examples ("Deploy...", "Monitor...", "Migrate..."). This is pragmatic and avoids false negatives.

- **B-2**: Spec says steps 11-12 appear for "B/C autonomy OR High risk." The conditional logic must handle the combined state correctly — user could select A + High risk and still need hooks.
  - **Resolution**: Confirmed — the spec already says "autonomy B/C OR risk High." Implementation must use OR logic: `(autonomyMode !== 'A') || (riskLevel === 'High')`. Verified the data model marks heartbeatStore and hooks as conditional. Correct.

### Category C: Recommendations
- **C-1**: Add a "Download as .txt" button alongside Copy. Low effort, high value for users who want to save locally.
  - **Decision**: Defer — out of scope per spec. Can be added in v2.
- **C-2**: The generated prompt should include a version identifier (e.g., "Generated by FLOYD Anvil v1.0") so users can track which version of the tool produced it.
  - **Decision**: Include — trivial to add, high value for traceability. Added to prompt template requirements.
- **C-3**: Consider adding a "dark/light" mode toggle.
  - **Decision**: Defer — enterprise dark is the spec. Ship one mode well.

## Second Pass Findings
- The spec's data model has `currentStep: number (1-12)` but the wizard may have fewer steps (10 if A+Low). The step counter should be dynamic based on visible steps, not a fixed 1-12.
  - **Fix**: Use a computed `totalSteps` value based on conditional visibility. Progress bar adapts.
- Clipboard API (`navigator.clipboard.writeText`) requires HTTPS or localhost in some browsers. Since this is a local HTML file opened via `file://`, we need a fallback using `document.execCommand('copy')` with a temporary textarea.
  - **Fix**: Implement both clipboard paths with try/catch fallback.

## Confidence Score
9/10 on technical feasibility. This is a well-bounded client-side problem.
